*الاسم مؤقت وقابل للتغيير.*

## 1. فكرة المشروع

مشروع يجمع بين الرؤية الحاسوبية (Computer Vision)، ومعالجة اللغة الطبيعية (NLP)، والشعر العربي، والمعرفة التاريخية، بهدف تحويل الصور التي يلتقطها المستخدم في حياته اليومية إلى رحلات أدبية وتاريخية تفاعلية.

عندما يلتقط المستخدم صورة أو يرفعها، يحلل النظام الصورة ويفهم عناصرها ومشهدها وسماتها البصرية، ويقترح المشاعر والمعاني التي قد توحي بها.

بعد ذلك يبحث النظام في قاعدة بيانات الشعر العربي عن القصائد التي تتناسب مع الصورة من الناحية البصرية والدلالية والعاطفية، ويعرض أفضل ثلاث قصائد مناسبة عند توفرها.

عندما يختار المستخدم إحدى القصائد، ينتقل إلى رحلة تاريخية تفاعلية قصيرة يتعرف خلالها على الشاعر وظروفه والأحداث المرتبطة بقول القصيدة، وصولًا إلى الأبيات ومصادرها التاريخية.

لا يهدف المشروع إلى عرض أبيات بجانب الصور فقط، بل إلى جعل الصورة مدخلًا لفهم الشعر العربي والتجارب الإنسانية التي تقف وراءه.

## 2. المشكلة

يمتلك التراث العربي عددًا هائلًا من القصائد التي تصف المشاهد الطبيعية والتجارب الإنسانية والمشاعر والأحداث التاريخية، لكن الوصول إلى الشعر المناسب لمشهد معين يتطلب عادة معرفة مسبقة بالشعراء أو الأبيات أو الكلمات المفتاحية. كما يقرأ كثيرون الأبيات دون معرفة الظروف التي دفعت الشاعر إلى قولها، فيفقدون جزءًا مهمًا من معناها.

- صعوبة اكتشاف القصائد المناسبة للمواقف والمشاهد اليومية.
- الاعتماد على البحث التقليدي بالكلمات المفتاحية.
- صعوبة البحث عن المعاني المجازية والعاطفية.
- انفصال النصوص الشعرية عن سياقها التاريخي.
- انتشار القصص الشعرية غير الموثقة.
- محدودية الطرق التفاعلية الحديثة لاستكشاف التراث الشعري العربي.

## 4. رحلة المستخدم

```
رفع صورة
  -> تحليل بصري: المشهد، العناصر، السمات، نقاط التركيز الممكنة        analyze_visual()
  -> تحليل عاطفي: مشاعر مقترحة + درجة عدم اليقين                    analyze_emotions()
  -> المستخدم يختار شعورًا رئيسيًا ونقطة تركيز
  -> استرجاع أفضل 3 قصائد مع سبب الترشيح ونوع الارتباط                 recommend_poems()
  -> المستخدم يختار قصيدة
  -> رحلة من ثلاث محطات: الشاعر -> الحكاية -> القصيدة                  get_historical_story()
  -> عرض الأبيات والمصادر
```

1. **التقاط الصورة:** مدن ومبانٍ، طبيعة وجبال، بحار وأنهار، سماء ونجوم، طرق وسفر، أشخاص ومواقف، حيوانات وطيور، أماكن قديمة، مشاهد يومية. يعتمد نطاق الدعم الفعلي في النسخة الأولى على النماذج والبيانات المستخدمة.
2. **تحليل الصورة:** نوع المشهد، العناصر، السمات الظاهرة، الألوان والإضاءة، نقاط التركيز الممكنة، المعاني المحتملة. **يُفصل دائمًا بين ما هو مرئي فعلًا وبين التفسيرات المحتملة.**
3. **تحليل المشاعر:** المشاعر المستهدفة: الحنين، الشوق، الحزن، الفرح، السكينة، الرهبة، التأمل. الفئات التي يصنفها النموذج فعليًا تعتمد على بيانات التدريب. **لا يدعي النظام معرفة مشاعر المستخدم الحقيقية**، بل يقترح الجو العاطفي للصورة، ويختار المستخدم شعورًا رئيسيًا أو يعدّله.
4. **نقطة التركيز:** صورة واحدة قد تحتوي البحر والغروب وطائرًا وشخصًا وحيدًا؛ يختار المستخدم العنصر أو المعنى الذي يريد استكشافه.
5. **البحث عن الشعر:** بالمعلومات البصرية والعاطفية والدلالية، لا بتطابق الكلمات فقط. تُعرض أفضل ثلاث قصائد مناسبة عند توفرها مع سبب الاختيار. **لا تُعرض قصائد غير مناسبة لإكمال العدد.**
6. **اختيار القصيدة:** مطلع القصيدة، الشاعر، أبيات مختارة، سبب المناسبة، نوع الارتباط، توفر القصة التاريخية.
7. **الرحلة التاريخية:** المحطة الأولى (الشاعر)، المحطة الثانية (الحكاية)، المحطة الثالثة (القصيدة)، ثم المصادر.

## 5. أنواع الربط بين الصورة والشعر

- **Visual Matching — مطابقة بصرية:** صورة بحر مع قصيدة تصف البحر وأمواجه.
- **Semantic Matching — مطابقة دلالية:** طريق طويل مع قصيدة عن الرحيل أو الغربة، حتى لو لم تذكر الطريق حرفيًا.
- **Emotional Matching — مطابقة عاطفية:** مكان قديم مع قصيدة عن الحنين والذكريات.

يمكن أن تجتمع الأنواع الثلاثة في ترشيح واحد، ويدعم النظام العلاقات المجازية والاستعارات والصور البلاغية.

## 6. الموثوقية التاريخية

يعتمد المشروع على الشعر الحقيقي والمصادر التاريخية بدل توليد قصص تخيلية بالذكاء الاصطناعي.

- مناسبة النظم موثقة: تُعرض القصة المرتبطة بها مع مصادرها.
- الروايات مختلفة: تُعرض الرواية الأقوى توثيقًا ويُوضَّح وجود اختلاف.
- مناسبة النظم مجهولة: تُعرض نبذة موثقة عن الشاعر **دون** الادعاء بأن أحداث سيرته سبب قول القصيدة.
- **ممنوع** اختلاق أحداث أو حوارات أو مصادر أو أبيات ونسبتها إلى شعراء حقيقيين.

قاعدة المعرفة: الشعراء، القصائد، العصور، الأحداث، الأماكن، الشخصيات، مناسبات النظم، الروايات المختلفة، المصادر، الأدلة.

## 7. مصادر البيانات

| المجال | المصادر | ملاحظات |
|---|---|---|
| الرؤية الحاسوبية | Places365، Open Images V7، Intel Image Classification | تُحدد البيانات النهائية حسب إمكانية الوصول والفئات المطلوبة |

## 8. التدريب والتقييم

يعتمد المشروع على **Transfer Learning** من نماذج مدربة مسبقًا بدل التدريب من الصفر: تجهيز البيانات، تقسيمها إلى Train/Validation/Test، Feature Extraction ثم Fine-tuning عند الجدوى، التقييم، الحفظ، الدمج. **مجرد تشغيل نموذج جاهز دون تدريب إضافي لا يحقق متطلب التدريب.**

| المكون | المقاييس |
|---|---|
| الرؤية الحاسوبية | Accuracy، Precision، Recall، F1، Confusion Matrix |
| المشاعر | Accuracy، Macro F1، أداء كل فئة، تحليل الأخطاء، مقارنة قبل التدريب وبعده |
| مطابقة الشعر | Precision@3، Recall@3، nDCG@3، تقييم بشري للملاءمة، جودة التفسير |
| المعرفة التاريخية | صحة النسبة، صحة الأبيات، تغطية المصادر، صحة الادعاءات، جودة التوثيق، سلامة العلاقات |

**تُستخدم نتائج اختبار حقيقية فقط، ولا تُختلق أي مقاييس أو مراجعات بشرية.**

## 11. التقنيات

Python، PyTorch، CLIP ونماذج بصرية مدربة مسبقًا، Arabic/Multilingual Embeddings، FastAPI، React، Vite، JSON أو SQLite، Pytest، GitHub Issues وProjects. **لن يُستخدم Streamlit.**

## 12. طريقة العمل في GitHub

1. اختر Issue وانقلها إلى In Progress.
2. أنشئ فرعًا: `feature/visual-*` أو `feature/emotion-*` أو `feature/poetry-*` أو `feature/history-*` أو `feature/integration-*` (مثال: `feature/emotion-training`).
3. نفذ المهمة وشغّل الاختبارات.
4. افتح Pull Request واكتب في الوصف `Closes #رقم_المهمة`.
5. يراجع عضو آخر: شادن وريناد تراجعان بعضهما، محمد وعمر يراجعان بعضهما، ومهام التكامل يراجعها عضوان على الأقل.
6. تُدمج التعديلات بعد الموافقة، وتُغلق المهمة بعد تحقق شروط القبول فقط.

لا تُرفع مفاتيح أو كلمات مرور أو أوزان ضخمة إلى المستودع؛ استخدم `.env` (غير مرفوع) وروابط تحميل للأوزان الكبيرة.
